# 0.7.5 베타 배포 검증

0.7.5는 소유자가 승인한 미서명 베타 정책과 공식 저장소 `Inkee1/mosaic`, 선택적 PostHog US 집계를 연결합니다. 미서명 경고를 유지하며, 안정 채널의 미서명 또는 파일 변조·검사 오류는 공개를 차단합니다. 동의 전 전송 없음, 동의 후 실제 수신 1회, 같은 UTC 날짜 중복 없음과 철회 후 중지를 별도 프로필에서 확인했습니다. `test_run: true` 이벤트는 운영 집계에서 제외합니다.

최종 공개 파일의 검증 근거는 해당 GitHub Release의 `RELEASE.json`입니다. core·UI·native 검사, 실제 설치·재설치·제거, 감사 대상 소스 커밋 및 파일 SHA-256이 같은 배포본에 연결되어야 공개할 수 있습니다. 아래는 이전 버전에서 확보한 기록이며 0.7.5 실행 결과를 대신하지 않습니다.

## 0.7.4 변경 기록

0.7.4는 빌드 의존성 취약점 수정과 배포 검증 자동화를 추가합니다. 소스·앱·설치 파일의 해시에 연결한 검사 결과만 공개 절차에 사용하며, 설치 검사를 실행하지 않은 환경은 미완료로 표시합니다. 이번 버전의 실제 결과는 `release/Mosaic-0.7.4-validation.json`을 확인하세요. GitHub에서 아직 실행하지 않은 워크플로는 실행 완료로 간주하지 않습니다.

## 0.7.3 변경 기록

0.7.3은 반복되는 사이트 권한 요청을 고칩니다. 0.7.2 실행 파일에서 같은 화면의 알림 요청을 두 번 거부했을 때 확인 창이 두 번 뜨는 현상을 재현했습니다. 화면·사이트별 이번 실행의 선택을 기억하고, 동시에 들어오는 같은 요청은 하나로 합칩니다. 아래 과거 검사 기록과 구별하여 `release/Mosaic-0.7.3-validation.json`의 현재 결과를 확인하세요.

## 0.7.2 변경 기록

0.7.2는 한국어·영어 표시, 시스템 언어 선택, 재시작 뒤 언어 설정 복원과 문의 주소를 추가합니다. 언어 전환은 사용자 작성 이름·내용, 사이트 언어, AI 응답과 동의 설정을 바꾸지 않습니다. 핵심·UI·패키지 검사 결과는 `release/Mosaic-0.7.2-validation.json`과 해당 버전의 설치 검사 보고서를 확인하세요. 소스에서 통과한 검사가 과거 설치 파일의 내용을 바꾸지는 않습니다.

아래는 이전 버전에서 확보한 검증 기록입니다. 0.7.2의 최종 설치 파일에는 같은 버전의 해시와 검사 보고서를 대조해야 합니다.

## 0.7.1 변경 기록

0.7.1은 별도 동의를 받는 사용자 수 집계와 PolyForm Noncommercial 1.0.0 조건을 추가합니다. 집계 프로젝트는 아직 연결하지 않았으므로 실제 수신 검증은 미완료입니다. 기본 꺼짐, 기존 로컬 동의와 분리, 저장 성공 전 전송 금지, 철회 경합, 재시작·날짜 경계, 저장 실패·종료 시 철회 보존을 검사했습니다. 관리 API 키·임의 호스트를 패키지에 넣을 수 없고 연결이 없으면 공개 검사에 실패합니다.

새 빌드와 UI 65개 검사가 통과했습니다. 최종 패키지의 설치·실행 결과는 아래 0.7.1 해시 연결 보고서로 확인하세요. 아래 표는 변경 전 0.7.0에서 확보한 기반 기능의 검증 기록이며 새 배포 파일 자체의 검증을 대신하지 않습니다.

새 테스트는 실패를 먼저 재현한 뒤 수정했습니다. 코드 검토에서 발견한 설치 위치와 데이터 폴더의 겹침, 실패한 동의 저장이 다른 저장에 의해 되살아나는 경합, 같은 버전의 오래된 배포 파일, 한글 배포자 서명 검사 문제를 보완했습니다.

최종 재검사 중 첫 화면 캡처의 `UnknownVizError`가 한 번 발생했습니다. [Electron 45.2.3의 캡처 구현](https://github.com/electron/electron/blob/v45.2.3/shell/browser/api/electron_api_web_contents.cc)에서 이미지 읽기 실패임을 확인하고, 입력 전 캡처만 한 번 재시도하도록 수정했습니다. 화면 준비 읽기는 2초, 전체 스크린샷은 5초의 대기 제한을 적용합니다. 실패·사용자 조작·중지 시 입력을 보내지 않으며, 이미 보낸 클릭이나 입력은 자동 반복하지 않습니다.

설정 화면은 실제 앱에서 1100×820 크기로 확인했고 작은 창 동작도 UI 테스트에 포함했습니다. 통계는 기본 꺼짐이며 저장이 성공한 동의 이후에만 수집합니다. 중단·오류·제공자 응답 종료를 숫자로 구분하며, 응답 종료를 사이트 작업 성공으로 표시하지 않습니다.

## 최종 파일과 설치 검사

앱 폴더만으로 설치판 검증을 대신하지 않습니다. 최종 설치·압축 파일은 다음 명령으로 검사하고, 해당 파일의 해시에 연결된 결과를 보관합니다.

```powershell
node scripts/test-installer-guards.mjs
node scripts/verify-windows-artifacts.mjs
node scripts/smoke-installer.mjs --run
node scripts/export-source.mjs
node scripts/audit-publication.mjs --package
node scripts/check-release.mjs --draft
node scripts/check-release.mjs --public
```

`release/Mosaic-0.7.1-win-x64-installer-smoke.json`의 `passed`, `packageManifestSha256`, `artifacts`를 최종 아티팩트 매니페스트와 대조하세요. 설치 검사는 압축 해제 후 파일 일치, 이전 버전 또는 같은 버전에서 교체, 설치된 앱 실행, 삭제 옵션 거부, 제거 후 프로필 보존을 확인합니다. `upgradeFrom`으로 실제 검사한 이전 버전을 구별합니다. 실제 설치·실행 중인 앱·바로가기가 있으면 검사를 거부합니다.

`verify-windows-artifacts.mjs`는 앱을 설치하지 않고 설치판·압축판을 풀어 파일을 비교합니다. `Mosaic-0.7.1-win-x64-artifact-verification.json`의 통과는 설치·제거 실행 결과를 대신하지 않습니다. 설치 검사 결과가 없거나 통과하지 않았다면 실제 설치 검증은 완료되지 않은 상태입니다.

소스/패키지 감사와 draft 검사의 최종 결과는 `publication-audit.json`, `release-check-draft.json`에 기록됩니다. 공개 정보와 라이선스·서명이 미정인 빌드의 public 검사는 실패해야 합니다. 파일을 다시 빌드·서명·수정한 뒤에는 해당 검사를 다시 실행하세요.

## 의존성 검사

검사 시 `npm audit --omit=dev`의 알려진 취약점은 0개였습니다. 전체 `npm audit`에는 설치 도구의 전이 의존성 minimatch에서 비롯된 **moderate 6개**가 남아 있습니다. 심각도 high/critical은 0개였으며 동일 원인의 영향을 받는 상위 패키지가 함께 집계됩니다.

[upstream 보안 공지](https://github.com/advisories/GHSA-g3hv-75wg-m249)에 따르면 공격자가 정한 glob 패턴이 처리될 때 과도한 CPU·메모리를 사용할 수 있습니다. 이 프로젝트에서는 설치 도구를 개발 환경에서 사용하고 배포 파일 선택 패턴은 저장소의 빌드 설정에서 정합니다. 해당 도구의 node_modules는 실행 폴더에 포함하지 않습니다. 보안 경고가 없다는 뜻은 아니며, 호환성이 확인되지 않은 강제 major 교체나 설치 도구의 과거 버전으로 강제 다운그레이드는 하지 않았습니다. 배포 전 upstream 갱신을 다시 확인하고 신뢰하지 않는 빌드 설정을 실행하지 마세요.

빌드 시 Lucide의 `use client` directive 경고가 출력됩니다. TypeScript 및 UI·데스크톱 검증은 통과했으며 이 앱은 React Server Components를 사용하지 않습니다.

## 남아 있는 결정과 검증 한계

- GitHub 저장소, 관리되는 문의 이메일과 배포자를 확정해야 합니다. 자체 라이선스는 PolyForm Noncommercial 1.0.0을 적용했습니다.
- 신뢰할 수 있는 코드 서명 후 최종 파일 검사를 다시 수행해야 합니다. 현재 파일은 미서명 미리보기입니다.
- 별도 동의 후 활성 설치 수를 보내는 기능은 구현했지만 운영 프로젝트가 미연결입니다. 실제 수신 확인, 보관기간·지역·문의처 확정 후 다시 패키징해야 합니다. 전체 고유 사용자 수로 해석하지 않습니다.
- CI 정의는 준비했지만 원격 GitHub 실행·웹사이트 게시·Release 업로드는 하지 않았습니다.
- 실제 계정 OAuth, 모든 외부 사이트, 모든 Windows/DPI/보안 정책 조합과 별도 깨끗한 PC는 검증하지 않았습니다. 자동화는 격리된 프로필·로컬 사이트·테스트 AI 제공자를 사용합니다.
- 개인정보·자격 증명 검사는 명시한 규칙과 선택한 배포 파일 범위에 한정됩니다. 전체 Git 이력의 보안 감사나 제3자 라이선스 법률 검토를 대신하지 않습니다.
